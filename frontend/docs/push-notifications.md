# Push notifications

The app uses `expo-notifications` with Expo Push Service on iOS and Android. Home → Notifications lets users opt in. It never prompts for permission on startup. Already-authorized devices register on startup and when returning to the foreground. Native token changes trigger registration again. Web and Expo Go skip native notification APIs.

## Configure delivery

1. Sign in and link your Expo project using `npx eas-cli@latest login` and `npx eas-cli@latest init`. Confirm that `app.json` contains the real `expo.extra.eas.projectId` generated by this command. No project ID is committed here because this repository has not been linked to an Expo account.
2. Set your organization's actual `expo.ios.bundleIdentifier` and `expo.android.package` in `app.json` before building. These identify the app in Apple and Firebase services.
3. For Android, register that package in Firebase, download `google-services.json`, set `expo.android.googleServicesFile` to its path, and upload the FCM v1 service account key using `npx eas-cli@latest credentials --platform android`. Keep the service account private; never bundle it in the app or commit it. Ignore downloaded credential/config files as appropriate for your organization.
4. For iOS, configure the APNs push key through Expo credentials/build setup. A physical iPhone build requires Apple Developer signing credentials.
5. Build with `npx eas-cli@latest build --profile development --platform android` or `--platform ios`. `eas.json` includes the development profile and `expo-dev-client` is installed. Install the build, then run `npx expo start --dev-client`. Rebuild after native dependency or plugin changes.

Official references: [SDK 58 notification API](https://docs.expo.dev/versions/v58.0.0/sdk/notifications/), [push setup and credentials](https://docs.expo.dev/push-notifications/push-notifications-setup/), and [sending notifications](https://docs.expo.dev/push-notifications/sending-notifications/).

## Test a remote push

On a test phone with the development build installed, open Home → Notifications → Enable notifications. Accept the OS permission prompt. A successful connection displays the development push token as selectable text. Tokens are not logged or shown in production builds.

Paste the token into the [Expo push notification tool](https://expo.dev/notifications). Set a title, body, default sound, and JSON data such as `{"url":"/genie"}`. Send to this test device only.

Alternatively, send from a trusted terminal, replacing the example token:

```bash
curl https://exp.host/--/api/v2/push/send \
  -H 'Content-Type: application/json' \
  -d '{"to":"ExponentPushToken[YOUR_DEVICE_TOKEN]","title":"Bulldog Bound","body":"Your test update has arrived.","sound":"default","channelId":"default","data":{"url":"/genie"}}'
```

Tap destinations are restricted to `/`, `/genie`, and `/notifications`; unknown or missing destinations open Home. Notification responses are cleared after handling to prevent repeat navigation on later launches.

Verify on both platforms:

- Foreground: notification banner appears, with sound subject to OS settings; tapping opens the destination.
- Background: notification arrives and tapping opens the destination.
- Terminated: tapping launches the app and opens the destination once.
- Permission denied: screen explains how to enable notifications in settings. Returning from settings refreshes permission and registration.
- Network unavailable: registration shows a retryable error; retry after reconnecting.
- Expo Go and web: dashboard works and notification controls explain availability.

## Connect a sender for real updates

Client registration enables receiving pushes; it does not send announcements automatically. The repository has no backend implementation. When a backend exists, upload each current Expo push token to an authenticated endpoint and associate it with the signed-in user/device. Update it after registration/rotation and disassociate it at sign-out. Reuse the `result.data` registration point in `NotificationsProvider.tsx` for that integration; do not place server secrets in the mobile app.

The backend should send via Expo Push Service, check push tickets and receipts, retry transient errors with backoff, and remove tokens on `DeviceNotRegistered`. Apply user notification preferences before sending. OS settings currently control opt-out for this prototype; there is no separate server subscription preference.
